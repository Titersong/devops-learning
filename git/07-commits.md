# Коммиты

## Создание коммитов

Коммит сохраняет подготовленное состояние проекта из индекса в историю репозитория. При создании коммита Git:

- создаёт новые объекты для изменённых файлов и каталогов.
- повторно использует неизменённые объекты.
- добавляет новый коммит в историю.
- перемещает `HEAD` текущей ветки на новый коммит.

Обычное создание коммита:

```bash
git commit -m "Сообщение"
```

Параметр `-s` добавляет строку `Signed-off-by`:

```bash
git commit -s -m "Сообщение"
```

Git хорошо работает с большим количеством небольших коммитов. Желательно, чтобы каждый коммит содержал одно логически завершённое изменение.

## Идентификаторы и теги

Каждый коммит получает уникальный хеш. Для обращения к коммиту можно использовать полный хеш или его уникальную короткую часть. Чтобы создать понятное имя для определённого коммита, используется тег:

```bash
git tag ver_10 <commit>
```

Например:

```bash
git tag ver_10 08d869
```

Перейти к отмеченному состоянию проекта можно командой:

```bash
git checkout ver_10
```

## Просмотр истории

Посмотреть историю коммитов можно с помощью:

```bash
git log
```

Коммиты выводятся от самого нового к самому старому. Краткий вывод истории:

```bash
git log --pretty=oneline
```

Посмотреть изменения, внесённые коммитами:

```bash
git log -p
```

Также можно начать просмотр с определённого коммита:

```bash
git log -p <commit>
```

## Отмена коммитов

### git revert

`git revert` отменяет изменения выбранного коммита, создавая новый коммит:

```bash
git revert <commit>
```

Существующая история при этом не удаляется. Такой способ подходит для изменений, которые уже могли получить другие разработчики.

Обозначения коммитов:

- `HEAD` - последний коммит.
- `HEAD~` - предыдущий коммит.
- `HEAD~2` - коммит на два шага назад.
- `<hash>` - полный или сокращённый хеш.
- `<tag>` - имя тега.

### git reset

`git reset` перемещает текущую ветку на другой коммит:

```bash
git reset HEAD~2
```

Основные режимы:

- `--soft` - перемещает ветку, но оставляет изменения в индексе;
- `--mixed` - перемещает ветку и убирает изменения из индекса;
- `--hard` - перемещает ветку, обновляет индекс и рабочие файлы.

Пример:

```bash
git reset --hard HEAD~2
```

`--hard` может удалить незакоммиченные изменения, поэтому его нужно использовать осторожно.

## Обслуживание репозитория

Оптимизировать и сжать репозиторий:

```bash
git gc
```

Проверить целостность объектов:

```bash
git fsck
```

Посмотреть, какие недоступные объекты будут удалены:

```bash
git prune -n
```

Удалить их:

```bash
git prune
```

## Поиск автора изменений

Команда `git blame` показывает, какой коммит и автор изменили каждую строку файла:

```bash
git blame <file>
```

Проверить определённый диапазон строк:

```bash
git blame -L 10,20 <file>
```

## Поиск плохого коммита

`git bisect` позволяет найти коммит, который внёс ошибку, разделяя диапазон коммитов пополам(бинарный поиск).

Начало поиска:

```bash
git bisect start
git bisect bad
git bisect good <good-commit>
```

После проверки выбранного Git коммита нужно указать результат:

```bash
git bisect good
```

или:

```bash
git bisect bad
```

Git продолжит делить оставшийся диапазон, пока не найдёт первый плохой коммит. Завершить поиск:

```bash
git bisect reset
```

Посмотреть историю бисекции:

```bash
git bisect log
```

При наличии тестового скрипта поиск можно автоматизировать:

```bash
git bisect run <script>
```

Скрипт должен возвращать `0` для хорошей версии и ненулевой код для плохой.

## Что важно запомнить

1. Коммит сохраняет подготовленные в индексе изменения в историю.
2. Каждый коммит имеет уникальный хеш и связан с предыдущими коммитами.
3. Теги позволяют присваивать коммитам понятные имена.
4. `git log` показывает историю проекта.
5. `git revert` отменяет изменения с помощью нового коммита.
6. `git reset` перемещает ветку и может изменять индекс и рабочие файлы.
7. `git blame` помогает найти автора конкретных строк.
8. `git bisect` быстро находит первый коммит, содержащий ошибку.
9. Небольшие логические коммиты упрощают поиск ошибок и работу с историей.
