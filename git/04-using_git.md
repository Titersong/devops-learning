# Использование Git

## Основные команды

Узнать установленную версию Git можно командой:

```bash
git --version
```

Для просмотра справки используются следующие команды:

``` bash
git help 
git help [subcommand]
git help --all
```

Например:

```bash
git help status
```

Команда `git help --all` показывает полный список команд Git. Некоторые из них предназначены для редких или более сложных задач.

## master vs. main

Исторически основная ветка нового репозитория называлась `master`. Сейчас во многих проектах вместо неё используется название `main`. Технически основная ветка может иметь любое имя. Её значение определяется правилами проекта, а не специальными свойствами внутри Git. Создать репозиторий и основную ветку `main` можно командами:

```bash
git init
git checkout -b main
```

Переименовать существующую локальную ветку `master` в `main` можно так:

```bash
git branch -m master main
```

Отправить новую ветку на удалённый репозиторий:

```bash
git push -u origin main
```

Проверить существующие локальные и удалённые ветки:

```bash
git branch -a
```

## Создание локального репозитория

Сначала нужно создать папку проекта и перейти в неё:

```bash
mkdir git-test
cd git-test
```

Затем папку можно превратить в Git-репозиторий:

```bash
git init
```

После выполнения `git init` внутри проекта создаётся скрытый каталог `.git`. В нём Git хранит историю проекта, настройки, объекты и информацию о ветках. Остальные файлы и каталоги проекта при инициализации не изменяются.

## Настройка автора коммитов

Git сохраняет имя и электронную почту автора каждого коммита. Для текущего репозитория их можно настроить командами:

```bash
git config user.name "Developer Name"
git config user.email "developer@example.com"
```

Если имя и электронная почта настроены глобально, повторять эту настройку для каждого нового репозитория не нужно.

## Добавление файла

Создадим новый файл:

```bash
echo "Some text" > example.txt
```

Чтобы Git начал отслеживать файл и включил его в следующий коммит, используется команда:

```bash
git add example.txt
```

Команда `git add` ещё не создаёт коммит. Она только добавляет текущее состояние файла в область подготовленных изменений. Проверить состояние репозитория можно командой:

```bash
git status
```

Она показывает:

- текущую ветку.
- новые файлы.
- изменённые файлы.
- изменения, подготовленные к коммиту.

## Просмотр изменений

Добавим ещё одну строку в файл:

```bash
echo "Another line" >> example.txt
```

Посмотреть изменения можно командой:

```bash
git diff
```

Команда `git diff` показывает изменения, которые ещё не были добавлены в область подготовленных изменений. Знак `+` перед строкой означает, что строка была добавлена:

```text
 some text
+another line
```

После изменения файла его нужно снова добавить:

```bash
git add example.txt
```

Это связано с тем, что `git add` сохраняет в области подготовленных изменений текущее состояние файла на момент выполнения команды.

## Создание коммита

Коммит сохраняет подготовленные изменения в истории репозитория:

```bash
git commit -m "Add example file"
```

Параметр `-m` позволяет сразу указать сообщение коммита. Если не использовать `-m`, Git откроет текстовый редактор, в котором нужно написать сообщение. Без сообщения коммит не будет создан. Сообщение должно кратко объяснять внесённое изменение:

```text
Add example file
Update Git notes
Fix configuration error
```

## Просмотр истории

Историю коммитов можно посмотреть командой:

```bash
git log
```

Для каждого коммита Git показывает:

- идентификатор коммита.
- автора.
- дату создания.
- сообщение.

Идентификатор позволяет однозначно определить конкретный коммит в истории проекта.

## Подтверждение происхождения изменений

Если проект использует DCO, к коммиту можно добавить параметр `-s`:

```bash
git commit -s -m "Add example file"
```

Он добавляет в сообщение коммита строку:

```text
Signed-off-by: Developer Name <developer@example.com>
```

Она подтверждает право разработчика на внесение этих изменений.

## Основной рабочий процесс

Обычная последовательность работы с Git выглядит так:

```text
Изменить файл
проверить состояние
посмотреть изменения
подготовить изменения
создать коммит
посмотреть историю
```

Для этого используются команды:

```bash
git status
git diff
git add <file>
git commit -m "Сообщение"
git log
```

## Что важно запомнить

1. `git init` создаёт новый Git-репозиторий и каталог `.git`.
2. В каталоге `.git` хранится история и служебная информация репозитория.
3. `git status` показывает текущее состояние репозитория.
4. `git diff` показывает изменения, которые ещё не подготовлены к коммиту.
5. `git add` добавляет текущее состояние файла в область подготовленных изменений.
6. `git add` не создаёт коммит.
7. `git commit` сохраняет подготовленные изменения в истории.
8. `git log` показывает историю коммитов.
9. Каждый коммит содержит автора, дату, сообщение и уникальный идентификатор.
10. Основная ветка обычно называется `main`, но технически может иметь любое имя.
