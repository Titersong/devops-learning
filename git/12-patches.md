# Использование патчей

## Зачем нужны патчи

Патч - это файл, содержащий изменения между версиями файлов или проекта. Патчи используются, когда:

- изменения нужно проверить перед объединением.
- не все разработчики используют Git.
- доступ к Git, SSH или HTTP ограничен.
- изменения передаются через электронную почту.

Обычный патч для двух каталогов можно создать командой(Linux):

```bash
diff -Nur stable_tree modified_tree > my_patch
```

Для двух файлов:

```bash
diff -u original_file modified_file > my_patch
```

Применить такой патч:

```bash
patch -p1 < my_patch
```

## Создание патчей в Git

Создать патч из незакоммиченных изменений:

```bash
git diff > patch_file
```

Основная команда для создания патчей из коммитов:

```bash
git format-patch
```

Создать отдельные патчи для трёх последних коммитов:

```bash
git format-patch -3
```

Git создаст файлы примерно с такими названиями:

```text
0001-First-commit.patch
0002-Second-commit.patch
0003-Third-commit.patch
```

Создать патчи для коммитов, появившихся после ответвления от `main`:

```bash
git format-patch main
```

Добавить строку `Signed-off-by`:

```bash
git format-patch -s -1 HEAD
```

Параметр `-s`, или `--signoff`, добавляет сведения об авторе из конфигурации Git.

## Отправка патчей по почте

Для отправки патча используется:

```bash
git send-email --to user@example.com 0001-First-commit.patch
```

Для работы команды может потребоваться настройка SMTP-сервера. Патч также можно отправить обычным почтовым клиентом. При этом важно:

- использовать обычный текст, а не HTML.
- отключить автоматический перенос строк.
- не изменять содержимое патча.
- желательно вставлять патч прямо в письмо.

## Проверка патча

Перед применением патча желательно проверить, подходит ли он к текущему состоянию проекта:

```bash
git apply --check 0001-First-commit.patch
```

Команда только выполняет проверку и не изменяет файлы.

Аналогичная проверка обычной утилитой `patch`(Linux):

```bash
patch --dry-run < 0001-First-commit.patch
```

## Применение через git am

Команда `git am` применяет патч и сразу создаёт новый коммит:

```bash
git am 0001-First-commit.patch
```

Она сохраняет информацию об авторе и сообщение исходного коммита. Если возник конфликт, его нужно исправить, после чего продолжить:

```bash
git am --resolved
```

Пропустить проблемный патч:

```bash
git am --skip
```

Отменить применение патчей и вернуться к исходному состоянию:

```bash
git am --abort
```

## Применение через git apply

Команда `git apply` применяет изменения к рабочим файлам:

```bash
git apply 0001-First-commit.patch
```

Она не создаёт коммит автоматически. После применения нужно самостоятельно выполнить:

```bash
git add .
git commit -m "Apply patch"
```

Проверить патч без применения:

```bash
git apply --check 0001-First-commit.patch
```

## Что важно запомнить

1. Патч содержит изменения между двумя состояниями проекта.
2. `git diff > file.patch` создаёт патч из текущих изменений.
3. `git format-patch` создаёт патчи из готовых коммитов.
4. Параметр `-s` добавляет строку `Signed-off-by`.
5. `git send-email` позволяет отправлять патчи по электронной почте.
6. `git apply --check` проверяет патч без изменения файлов.
7. `git am` применяет патч и создаёт коммит.
8. `git apply` применяет изменения, но не создаёт коммит.
9. `git am --abort` отменяет процесс применения патчей.
