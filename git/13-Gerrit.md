# Gerrit и проверка кода

## Распределённая разработка

Обычный рабочий процесс Git выглядит так:

1. Разработчик вносит изменения в код.
2. Создаёт коммит.
3. Публикует изменения через `push` или запрос на объединение.
4. Изменения проверяются, принимаются или возвращаются на доработку.

В некоторых проектах окончательное решение принимает один сопровождающий разработчик. Для более распределённой проверки кода можно использовать Gerrit.

## Что такое Gerrit

**Gerrit** - система проверки кода, построенная на основе Git. Она добавляет дополнительный этап между разработчиком и основным репозиторием:

1. Разработчик отправляет изменение в Gerrit.
2. Рецензенты проверяют код и оставляют комментарии.
3. Изменение либо возвращают на доработку, либо одобряют.
4. После одобрения оно попадает в основной репозиторий.

Для удобной проверки рекомендуется делать один коммит для одного логического изменения.

## Проверка изменений

Разработчик отправляет изменение в Gerrit, после чего рецензенты могут:

- изучить код.
- оставить комментарии.
- запросить исправления.
- отклонить изменение.
- одобрить его и отправить в основной репозиторий.

Gerrit сохраняет историю комментариев и решений. Благодаря этому можно узнать, почему изменение было принято, отклонено или доработано.

## Что важно запомнить

1. Gerrit работает поверх Git.
2. Он добавляет обязательный этап проверки кода.
3. Изменения проверяют один или несколько рецензентов.
4. Рецензент может принять изменение, отклонить его или запросить доработку.
5. Один коммит желательно посвящать одному логическому изменению.
6. Gerrit сохраняет комментарии и историю обсуждения изменений.
