# Git и системы управления версиями

## Переход между системами

Проекты можно переносить из одной системы управления версиями в другую. Если просто скопировать рабочие файлы и создать новый Git-репозиторий, предыдущая история изменений будет потеряна. Поэтому для переноса используют специальные инструменты, которые импортируют не только файлы, но и историю проекта. Например, `git svn` позволяет импортировать репозиторий Subversion в Git.

## RCS

RCS - старая система управления версиями, которая обычно хранит репозиторий в каталоге `RCS`. Она использует блокировку файлов:
- незаблокированный файл нельзя изменять.
- после блокировки изменять его может только владелец блокировки.
Из-за этого разработчикам приходится работать с файлами по очереди, что плохо подходит для большой команды.

## CVS

CVS была создана как более удобная система по сравнению с RCS. Она использует централизованный репозиторий. Каждый разработчик получает собственную рабочую копию файлов, вносит изменения и затем отправляет их обратно в общий репозиторий. CVS позволяет нескольким разработчикам одновременно работать над одним проектом и объединять изменения.

## Subversion

Subversion, или SVN, была разработана как преемник CVS. Она также является централизованной системой, но лучше работает с каталогами, переименованием файлов и общими наборами изменений. Коммиты в SVN атомарны: либо весь коммит сохраняется успешно, либо не сохраняется ни одна его часть. Subversion может работать через отдельный SVN-сервер или через HTTP-сервер Apache.

## Git

Git был создан Линусом Торвальдсом в 2005 году для разработки ядра Linux после прекращения бесплатного использования BitKeeper. Git хранит состояние проекта с помощью объектов:
- **blob** - содержимое файла;
- **tree** - структура каталогов и имена файлов;
- **commit** - снимок состояния проекта и ссылка на предыдущую историю.

Git является распределённой системой. Каждый клонированный репозиторий содержит всю кодовую базу и историю проекта. На техническом уровне в Git нет обязательного центрального репозитория. GitHub или GitLab могут считаться главными репозиториями внутри команды, но это определяется правилами проекта, а не самим Git.

## Что важно запомнить

1. RCS заставляет разработчиков по очереди блокировать и изменять файлы.
2. CVS и Subversion используют центральный репозиторий.
3. Subversion создавалась как более современная замена CVS.
4. Git является распределённой системой управления версиями.
5. Каждый Git-репозиторий может содержать полную историю проекта.
6. Git не требует обязательного центрального репозитория.
7. При переносе проекта важно сохранить не только файлы, но и историю изменений.
