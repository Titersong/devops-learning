# Управление локальными и удаленными репозиториями

## Совместная работа

Git является распределённой системой: каждый разработчик может иметь собственный полноценный репозиторий с полной историей проекта. Отдельные репозитории удобны, когда:

- разработчик работает автономно.
- над проектом работают распределённые команды.
- отдельные части проекта развиваются независимо.

Основные операции с удалёнными репозиториями:

- `clone` - создание локальной копии.
- `fetch` - получение изменений.
- `pull` - получение и объединение изменений.
- `push` - отправка локальных коммитов.
- публикация - предоставление другим пользователям доступа к репозиторию.

## Bare-репозиторий

**Bare-репозиторий** - это репозиторий, который не содержит рабочего каталога и не используется для редактирования файлов. Он служит общим хранилищем, в которое отправляют изменения и из которого выполняют клонирование. Создать bare-копию можно так:

```bash
git clone --bare <repository> <bare-repository>
```

Например:

```bash
git clone --bare git-test git-test-clone
```

## Клонирование

Команда `git clone` создаёт локальную копию репозитория:

```bash
git clone <repository-address>
```

Git поддерживает разные способы доступа:

```text
file:///path/to/repository
git://server/path/to/repository
ssh://user@server/path/to/repository
user@server:/path/to/repository
http://server/path/to/repository
https://server/path/to/repository
```

При клонировании создаётся обычный репозиторий с рабочими файлами и каталогом `.git`.

## Просмотр ссылок

Посмотреть ветки, теги и другие ссылки локального репозитория:

```bash
git show-ref
```

Посмотреть ссылки удалённого репозитория без его клонирования:

```bash
git ls-remote <repository-address>
```

## Публикация через git daemon

Чтобы предоставить сетевой доступ к bare-репозиторию через протокол `git://`, в нём создаётся файл:

```bash
touch git-daemon-export-ok
```

Затем запускается демон:

```bash
git daemon
```

Можно указать общий базовый каталог:

```bash
git daemon --base-path=<path>
```

По умолчанию такой доступ обычно позволяет клонировать репозиторий и получать изменения, но не отправлять их. Разрешить отправку изменений:

```bash
git daemon --enable=receive-pack
```

Для отдельного репозитория доступ на запись можно включить в его конфигурации:

```ini
[daemon]
    receivepack = true
```

## Доступ через HTTP

Для доступа через HTTP необходим настроенный веб-сервер. В bare-репозитории нужно выполнить:

```bash
git --bare update-server-info
```

После этого репозиторий можно клонировать по HTTP или HTTPS:

```bash
git clone http://server/repository
git clone https://server/repository
```

## Создание архива

Команда `git archive` создаёт архив рабочих файлов без каталога `.git`. Архив текущего состояния создается так:

```bash
git archive --verbose HEAD | bzip2 > myproject.tar.bz2
```

Архив определённой версии или тега:

```bash
git archive --verbose v1.7.1 | bzip2 > myproject_v1.7.1.tar.bz2
```

## Получение изменений

`git fetch` загружает изменения из удалённого репозитория, но не объединяет их с текущей веткой:

```bash
git fetch
```

После этого изменения можно объединить вручную:

```bash
git merge origin/main
```

## Pull

`git pull` получает изменения и сразу объединяет их с текущей веткой:

```bash
git pull
```

Эта операция примерно соответствует:

```bash
git fetch
git merge origin/main
```

Можно явно указать удалённый репозиторий и ветку:

```bash
git pull origin main
```

## Push

`git push` отправляет локальные коммиты в удалённый репозиторий:

```bash
git push <repository> <branch>
```

Например:

```bash
git push origin main
```

Перед `push` желательно убедиться, что локальная ветка актуальна и рабочий каталог не содержит незавершённых изменений. Обычно изменения отправляются в bare-репозиторий, поскольку у него нет рабочего каталога, который мог бы не соответствовать полученным коммитам.

## Что важно запомнить

1. Каждый Git-репозиторий может содержать полную историю проекта.
2. `git clone` создаёт локальную копию репозитория.
3. Bare-репозиторий используется как общее хранилище без рабочих файлов.
4. `git fetch` только загружает изменения.
5. `git pull` загружает и объединяет изменения.
6. `git push` отправляет локальные коммиты в удалённый репозиторий.
7. Git поддерживает доступ через локальные пути, Git, SSH, HTTP и HTTPS.
8. `git show-ref` показывает локальные ссылки, а `git ls-remote` - ссылки удалённого репозитория.
9. `git archive` создаёт архив проекта без служебного каталога `.git`.
