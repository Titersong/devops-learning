# Слияния (merges)

## Что такое слияние

Слияние объединяет изменения из разных веток в одну. Если разработчики изменяли разные файлы или разные части одного файла, Git обычно объединяет изменения автоматически. Если изменения затрагивают одни и те же строки, возникает конфликт, который необходимо разрешить вручную. Слияние можно рассматривать как обратный процесс по отношению к созданию ветки.

## Слияние веток (merge)

`merge` объединяет изменения одной ветки с текущей веткой. Чтобы добавить изменения из ветки `develop` в `main`, нужно сначала перейти в `main`, а затем выполнить слияние:

```bash
git checkout main
git merge develop
```

После этого ветка `main` будет содержать изменения из `develop`. Перед слиянием желательно проверить состояние репозитория с помощью `git status`. Незавершённые изменения лучше заранее добавить и закоммитить, чтобы они не мешали процессу слияния.

## Конфликты слияния

Если ветки изменяли разные файлы или разные части одного файла, Git обычно объединяет изменения автоматически. Конфликт возникает, когда две ветки по-разному изменили одну и ту же часть файла. В таком случае Git добавляет в файл специальные маркеры:

```text
<<<<<< HEAD
содержимое текущей ветки
=======
содержимое присоединяемой ветки
>>>>>> develop
```

Где:

- `<<<<<<< HEAD` - версия текущей ветки.
- `=======` - разделитель.
- `>>>>>>> develop` - версия присоединяемой ветки.

Чтобы разрешить конфликт, нужно:

1. Открыть конфликтный файл.
2. Выбрать правильный вариант содержимого или объединить оба варианта.
3. Удалить служебные маркеры.
4. Добавить исправленный файл в индекс.
5. Создать коммит слияния.

```bash
git add <file>
git commit -m "Resolve merge conflict"
```

После создания коммита слияние будет завершено.

## Отмена слияния

Если слияние было выполнено преждевременно или привело к большому количеству проблем, можно вернуться к прежнему состоянию ветки:

```bash
git reset --hard main
```

Параметр `--hard` изменяет рабочие файлы, поэтому перед его использованием нужно убедиться, что важные незакоммиченные изменения отсутствуют.

## Перебазирование (rebase)

`rebase` переносит коммиты одной ветки поверх текущего состояния другой ветки. Например, чтобы обновить ветку `develop` относительно `main`, нужно сделать:

```bash
git checkout develop
git rebase main develop
```

Во время перебазирования Git:

1. Временно убирает коммиты ветки `develop`.
2. Переносит ветку на последнее состояние `main`.
3. Повторно применяет коммиты `develop` поверх обновлённой основы.

Из-за этого история ветки переписывается, а хеши перенесённых коммитов изменяются.

## Конфликты при rebase

Во время перебазирования также могут возникнуть конфликты. После исправления конфликтного файла его нужно добавить в индекс, `git add <file>`.

Затем продолжить перебазирование:

```bash
git rebase --continue
```

Если перебазирование привело к проблемам, его можно полностью отменить:

```bash
git rebase --abort
```

После этого репозиторий вернётся к состоянию до начала `rebase`.

## Опасность rebase

`rebase` переписывает историю коммитов. Поэтому его не следует применять к ветке, коммиты которой уже получили другие разработчики. Обычно `rebase` безопаснее использовать для собственных локальных коммитов, которые ещё не были опубликованы.

## Ключевое отличие

```text
merge - объединяет ветки и сохраняет существующую историю.
rebase - переносит коммиты на новое основание и переписывает историю.
```

## Что важно запомнить

1. `git merge` объединяет изменения выбранной ветки с текущей.
2. Перед слиянием желательно закоммитить незавершённые изменения.
3. Git автоматически объединяет изменения, если они не конфликтуют.
4. Конфликты в одних и тех же строках разрешаются вручную.
5. После разрешения конфликта файл нужно добавить через `git add` и закоммитить.
6. `merge` сохраняет историю разветвления.
7. `rebase` переносит коммиты на другое основание и изменяет их историю.
8. `git rebase --continue` продолжает перебазирование после исправления конфликта.
9. `git rebase --abort` отменяет перебазирование.
10. Не следует переписывать с помощью `rebase` историю, которой уже пользуются другие разработчики.
