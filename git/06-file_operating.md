# Управление файлами и индексом

## Категории файлов

С точки зрения Git файлы рабочего проекта делятся на три категории.

### Отслеживаемые файлы

**Отслеживаемые файлы** уже известны Git и находятся в репозитории. Они могут быть:

- неизменёнными.
- изменёнными.
- добавленными в индекс для следующего коммита.

После добавления нового файла с помощью `git add` он становится отслеживаемым.

### Игнорируемые файлы

**Игнорируемые файлы** не должны отслеживаться Git. Правила игнорирования записываются в файл:

```text
.gitignore
```

В нём можно указывать конкретные имена файлов или шаблоны. Например, игнорировать все файлы с расширением `.o`:

```text
*.o
```

Файл `.gitignore` действует для каталога, в котором он находится, и его подкаталогов. С помощью `!` можно создать исключение из правила:

```gitignore
*.ko
!my_driver.ko
```

В этом примере все файлы `.ko` игнорируются, кроме `my_driver.ko`.

### Неотслеживаемые файлы

**Неотслеживаемые файлы** ещё не были добавлены в Git и не подходят под правила `.gitignore`. Это могут быть:

- недавно созданные файлы;
- временные файлы;
- другие файлы, о которых Git пока ничего не знает.

После выполнения `git add` файл становится отслеживаемым.

## Основные команды работы с файлами

### git add

Команда `git add` добавляет новое или изменённое состояние файла в индекс:

```bash
git add <file>
```

Можно добавить сразу все файлы:

```bash
git add .
```

После выполнения `git add` изменения только подготавливаются. Они не попадут в историю репозитория до выполнения:

```bash
git commit
```

Параметр `-u` обновляет в индексе только файлы, которые уже известны Git:

```bash
git add -u
```

Параметр `-i` запускает интерактивный выбор изменений:

```bash
git add -i
```

### git rm

Команда `git rm` удаляет файл из рабочего каталога и индекса:

```bash
git rm <file>
```

Удаление будет окончательно зафиксировано в репозитории только после создания нового коммита. При этом старые версии файла остаются в истории проекта. Чтобы удалить файл только из индекса, но оставить его в рабочем каталоге, используется параметр `--cached`:

```bash
git rm --cached <file>
```

### git mv

Команда `git mv` перемещает или переименовывает файл:

```bash
git mv <old-name> <new-name>
```

Эта команда эквивалентна следующей последовательности:

```bash
mv oldfile newfile
git rm oldfile
git add newfile
```

При переименовании содержимое файла остаётся прежним. Изменяется его имя или расположение в индексе.

### git ls-files

Команда `git ls-files` показывает файлы, находящиеся в индексе:

```bash
git ls-files
```

Чтобы вывести неотслеживаемые файлы, не показывая файлы из стандартных правил игнорирования, используется:

```bash
git ls-files --others --exclude-standard
```

- `--others` показывает неотслеживаемые файлы;
- `--exclude-standard` применяет правила из `.gitignore` и другие стандартные исключения.

## Что важно запомнить

1. Файлы могут быть отслеживаемыми, игнорируемыми или неотслеживаемыми.
2. `.gitignore` содержит правила для файлов, которые Git не должен отслеживать.
3. `git add` добавляет новое состояние файла в индекс, но не создаёт коммит.
4. `git rm` удаляет файл из рабочего каталога и индекса.
5. `git rm --cached` удаляет файл из индекса, но оставляет его на компьютере.
6. `git mv` используется для перемещения и переименования файлов.
7. `git ls-files` показывает файлы, находящиеся в индексе.
8. Команды работы с файлами не изменяют историю до выполнения `git commit`.
