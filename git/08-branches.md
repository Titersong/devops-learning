# Ветки

## Что такое ветка

Ветка - отдельное направление разработки проекта. Ветки позволяют:

- разрабатывать новые функции отдельно от стабильной версии.
- исправлять ошибки, не затрагивая основную разработку.
- поддерживать несколько версий программы.
- параллельно работать над разными задачами.

В одном репозитории может существовать много веток, но активной одновременно является только одна. Рабочие файлы соответствуют текущей ветке и могут измениться после переключения. Основная ветка обычно называется `main`, однако технически она не отличается от остальных веток.

## Ветка и тег

Ветка и тег указывают на определённый коммит, но используются по-разному.

**Ветка** представляет направление разработки. При создании новых коммитов её указатель перемещается вперёд.

**Тег** отмечает конкретное состояние проекта и обычно остаётся неизменным.

Например:

```text
main - развивающаяся основная ветка
develop - ветка разработки
v1.0 - тег определённой версии
```

Не рекомендуется использовать одинаковые названия для веток и тегов.

## Создание ветки

Создать новую ветку можно с помощью команды:

```bash
git branch <branch-name>
```

Например:

```bash
git branch develop
```

Новая ветка создаётся на основе текущего коммита, но Git не переключается на неё автоматически. Создать ветку от определённого коммита или тега:

```bash
git branch <branch-name> <starting-point>
```

Посмотреть список веток:

```bash
git branch
```

Текущая ветка будет отмечена символом `*`. Более подробно посмотреть состояние веток:

```bash
git show-branch
```

Удалить ветку:

```bash
git branch -d <branch-name>
```

Нельзя удалить ветку, которая сейчас является активной.

## Переключение между ветками

Переключиться на другую ветку:

```bash
git checkout <branch-name>
```

Например:

```bash
git checkout develop
```

После переключения:

- `HEAD` указывает на последний коммит выбранной ветки.
- рабочие файлы изменяются в соответствии с состоянием этой ветки.
- другие ветки остаются в репозитории.

Вернуться в основную ветку:

```bash
git checkout main
```

Git может отказаться переключать ветку, если в рабочем каталоге есть незакоммиченные изменения, которые могут быть потеряны.

## Создание и переключение одной командой

Создать новую ветку и сразу перейти на неё:

```bash
git checkout -b <branch-name>
```

Например:

```bash
git checkout -b develop
```

Это равнозначно двум командам:

```bash
git branch develop
git checkout develop
```

Также можно указать начальную точку:

```bash
git checkout -b <branch-name> <starting-point>
```

## Просмотр старой версии файла

Посмотреть содержимое файла из определённого коммита или тега:

```bash
git show <commit>:<path>
```

Например:

```bash
git show v2.4.1:src/myfile.c
```

Восстановить старую версию файла в рабочем каталоге:

```bash
git checkout <commit> <path>
```

Например:

```bash
git checkout v2.4.1 src/myfile.c
```

После восстановления файл нужно добавить в индекс и закоммитить, чтобы сохранить изменение в истории.

## Что важно запомнить

1. Ветка представляет отдельное направление разработки.
2. В одном репозитории может быть много веток, но активна только одна.
3. `git branch` создаёт ветку, но не переключает на неё.
4. `git checkout` переключает текущую ветку и обновляет рабочие файлы.
5. `git checkout -b` создаёт ветку и сразу переключается на неё.
6. Ветка перемещается при новых коммитах, а тег обычно остаётся неизменным.
7. `git branch -d` удаляет неактивную ветку.
8. `git show` позволяет посмотреть старую версию файла.
